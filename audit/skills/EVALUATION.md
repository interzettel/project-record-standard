# Agent workflow evaluation

The cases are synthetic. Sam and Loomglass are fixture identities; no real project was migrated and no private user source was included. The canonical package is tested separately from owner adoption and actual screen-reader output.

## Method and limits

Used the installed Superpowers `writing-skills` process and its test-driven approach. The initial upstream reference was pinned at `2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`; the installed skill was read when it became exposed. Personal skills were initialized with Skill Creator, validated in place, committed and pushed. The canonical `skills/` directory distributes the same workflow bodies.

Five fresh-context controls handled all ten requests in `cases.md` without the new skills. Their raw responses are in `controls/`. They already preserved branding, unsupported evidence and approval boundaries well. The observed gaps were concrete, reusable handoff artifacts, tool/routing discovery and a purpose/scope-first scouting cycle; we do not claim broad baseline safety failures.

Each workflow then received five preparation samples using its skill. These are bounded application/wording checks, not proof that arbitrary agents reliably handle every repository. The controls saw the complete request list; individual skill samples saw the selected request, so their outputs are not a controlled estimate of causal improvement. Some runs were resumed after actual capacity failures; capacity failure was never scored as success.

The GitHub initial iteration exposed a real alias-direction mistake in one sample. The linter expects native label → shared meaning. The skill added that exact structural contract and JSON example; five further samples used the correct direction. Initial and refined responses are retained. No invented rationalization table was added for this formatting/reference failure.

## Executable applications

The cold application inspected a branded repository, its brief and an unmerged exporter branch. It found no runnable importer despite the brief's claim; the exporter was a stub. It created overview/discovery/adoption, a private proposed seven-leaf plan, WBS mapping and three checkpoints. Required/retained work remained 0/7, milestones 0/3. Original README/site/AGENTS/brief and branch refs were preserved. An empty 0/0 observation was retained. Check, pipeline, normalized validation, compare, status, repeat generation, installation preview and public-export refusal were exercised.

The hot application preserved all five authored files and available Git history. An existing adapter reconciled required 4/6 (66.7%) and retained 5/8 (62.5%) exactly. Native gate completion remained 1/3 (33.3%); missing Sam acceptance was explicitly separate and prevented an unsupported cutover. Two canonical builds and a vendored-runtime recovery build matched. Repeat verification preserved 67 preparation files. An actual reference-pin mismatch stopped a run; the failed attempt, changed references and refreshed pin were retained before recovery.

Application reports and selected raw evidence are under `application/`. They record the exact runtime/reference bytes used during authoring. Subsequent percentage rounding changed the runtime; the final package checks/replays are recorded separately rather than retroactively relabelling those agent runs.

## Deterministic checks

Runtime tests cover additive installation, previews/repeats, interrupted installation, owned-file edits, symlink/path and temporary-file collisions, package installation, collection failures/partial coverage, explicit source age, private export, unique accounting, history, evidence and release revision matching. A discovered rounding mismatch at 13/16 was reproduced and corrected: Python and browser now show 81.3%; equal-milestone means use unrounded shares.

Metadata validation and CI verify packaging/discovery structure. They do not establish agent behavior, authenticate an owner or observe a screen reader. Native GitHub issue/Project mutation was not exercised against real project repositories; those migrations and integrations remain separate authorized work.

Manual gates remain actual screen-reader output and designated owner acceptance. No result here closes them.
