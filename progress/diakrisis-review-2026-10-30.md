## Work-management lessons

| Lesson | Decision and PRS treatment |
| --- | --- |
| One authoritative home per fact | Adopt; preserve the host's declared writer per field. Do not move PRS completion authority to GitHub by default. |
| Overview before decomposition; plans explain sequence | Adopt; retain the overview, canonical ledger and linked delivery plan. Reserve runbook for operation/recovery. |
| Observable criteria and shared Definition of Done | Adapt to artifact and project policy. Historical Done is not silently recertified; a negative experiment may satisfy its own criterion. |
| Implemented / Done / accepted / delivered | Adapt to separately inspectable claims, with integration, verification and channel/environment evidence distinct. Decline a universal merge-first definition of implementation or a forced linear pipeline. |
| Epic / feature / story / task | Optional host mapping. Decline a mandatory ladder, renaming stable IDs, or counting parent and leaf twice. |
| Findings, actions, decisions and evidence | Adopt the distinctions; route continuing action to an existing or explicitly selected work item. Preserve dated observations and supersession. |
| Origin versus effect; typed relationships | Adopt as vocabulary for future mapped work. Do not silently add runtime enums or make all links blocking. |
| Dependency readiness and graph depth | Adapt: include holds, authority, capacity and unknown evidence. Depth is structural, not a date or permission. Runtime formulas remain #23. |
| Ordered backlog, review and reflection | Adapt to finite goals and useful solo cadence. Decline mandatory Scrum ceremonies or fixed professional agent roles. |
| Migration and schema checks | Adopt inventory/preview/history preservation. Schema and span checks establish structure and quote location, not factual truth. |
